# 찐친소 신청 UX

디자인 기준: 저장소 루트의 `design.md` (사용자가 제공한 디자인 시스템 v1.0).

- 대화·주선자 선택·말풍선·전송 버튼을 제거한다. 은행 앱처럼 한 화면에 한 질문만 표시한다.
- 챕터 1 나에 대해: 기본 정보와 생활·취향. 챕터 2 원하는 인연: 이상형·조건·피하고 싶은 소속. 챕터 3 신청 마무리: 사진·연락처·추천인·초대 코드·소개 방식·동의·최종 확인.
- 기존 문항, 필수/선택 여부, 선택값, 한글 JSON 키, Apps Script 주소와 인증 토큰을 유지한다.
- 주선자 선택 UI는 제거한다. 기존 서버 호환을 위해 신규 신청의 주선자 값은 f로 유지하고, 이전 초안·신청의 값은 보존한다. 서버의 f/m 검증이나 운영 데이터는 변경하지 않는다.
- 기본 시스템 글꼴, 크림·아이보리 표면, 브라운 텍스트, 로즈우드 행동 색상을 쓴다.
- `tokens.json`이 의미 토큰의 원본이다. `node design/build.cjs`로 라이트/다크 CSS와 대비 결과를 갱신한다.
- 선택하면 즉시 다음 질문으로 이동한다. 직접 입력은 다음 버튼 또는 Enter로 진행하고, 긴 답변은 Enter로 줄바꿈한다. 선택 항목은 건너뛰기를 제공한다.
- 상단에 3개 챕터와 챕터 내 진행 위치를 표시한다. 이전 질문·진행했던 챕터로 돌아가도 답변을 유지한다. 최종 확인 화면에서 항목을 수정하면 확인 화면으로 복귀한다.
- 필드별 검증, 초안과 진행 위치 복원, 사진 압축, 중복 제출 방지와 동일 신청ID 재시도를 제공한다. 사진이 사라진 새로고침에서는 사진 단계로 복귀한다.
- 초안 텍스트는 기존과 같이 sessionStorage에만 저장한다. 사진은 새로고침 시 다시 선택해야 하며, 파일 선택 영역에 필요한 수량을 표시한다.
- 접수 완료 후 신청 조회·수정·철회를 지원한다. 체험 모드는 실제 서버에 전송하지 않는다.

## 검증

`tests/form.cjs`는 Playwright 브라우저에서 신청서를 작성하고 실제 `server/Code.gs`를 서비스 모형으로 실행해 접수, 실패 후 재시도, 수정, 조회, 철회를 확인한다. 실제 운영 서버에는 테스트 신청을 보내지 않는다.

실행: `node design/build.cjs`, `node tests/form.cjs` (Playwright 설치 필요).
설치된 Chrome을 사용할 때는 `CHROME_PATH`에 실행 파일을 지정한다. `SCREENSHOT_DIR`를 지정하면 모바일·PC·다크 모드 화면을 저장한다.

이전 채팅 흐름을 직접 조작하는 기존 테스트는 새 폼용 테스트로 대체된다. 기존 `tests/server.cjs`에는 현재 서버의 accountAccess 응답을 기대값에서 누락한 기존 실패가 있다.

## 첫 화면·파티·표시 문구 업데이트

- 기본 진입은 원래 서비스 소개 3개를 유지한 홈 화면이다. 슬라이드, 좌우 화살표, 점 탐색과 진행 방식 안내를 제공한다.
- 소개 아래에 찐친소 풀에 등록하기와 파티 신청하기를 둔다. 풀은 `?view=pool`, 파티는 별도 `party.html`로 이동한다. 뒤로 가기와 체험 모드도 유지한다.
- 파티 페이지는 포스터를 넣을 공간과 준비 중 안내만 제공한다. 일정·장소·가격·모집 상태를 임의로 만들지 않는다. 포스터가 준비되면 `party.html`의 poster-slot을 img.party-poster로 교체한다.
- 입력 플레이스홀더는 원래 main의 문구를 복원했다. 질문별 반복 진행 안내를 없애고, 연봉·자산의 개별 전달 안내는 동의 화면으로 통합했다.
- 761px 이상 PC에서는 건너뛰기와 다음 버튼을 한 줄에 놓고 다음 버튼은 320px, 건너뛰기는 내용 너비의 텍스트 버튼으로 표시한다.
- 사용자 요청에 따라 찐친소 표시 글자에 KT Y클로버체 Bold를 적용한다. 공식 웹폰트를 변경 없이 로컬에 포함하고, 출처는 THIRD_PARTY_NOTICES.txt에 기록한다. 본문과 입력란은 시스템 글꼴을 유지한다.


## 11/14 빼빼로 데이 파티

- 홈에 실제 행사명·일정과 여자 마감 상태를 표시한다. 첫 소개의 보조 문구는 “고려대·서울대 출신의 안목으로 / 좋은 만남을 정성껏 준비해요.”로 변경했다.
- 상세는 제공된 원본 포스터와 큰 신청하기 버튼만 표시한다. 두 번째 포스터는 party-config.js 배열에 추가한다.
- 풀과 같은 한 질문씩 진행하는 UI로 성별, 이름, 출생연도, 간단한 자기소개, 연락처만 받는다. 별도의 개인정보 동의와 최종 확인을 제공한다.
- 여자 마감은 UI의 비활성 선택지와 서버의 거절 로직으로 적용한다. 테스트 데이터로 실제 server/Code.gs를 실행해 거절과 저장을 확인한다.
- 파티 데이터는 파티신청 탭에 저장한다. 풀 신청 탭, 사진 폴더와 이전/정리 루틴에서 분리한다. 같은 ID의 재시도는 한 번만 저장한다.
- 현재 저장 코드는 로컬 변경이다. 실제 운영 웹 앱에 Code.gs 새 버전을 배포해야 실접수가 연결된다. 미지원 서버에서 성공 화면을 보여주지 않는다.

## 신청 화면 타이포그래피·동의 간격

- 풀과 파티 신청에 공통 타입 스케일을 적용한다: 제목 28/36px, 본문 16/26px, 보조 문구 14/22px, 단문 입력 20/28px. 버튼은 16px, 원래 브랜드 표시 글꼴은 유지한다.
- 동의 안내 박스는 20px 패딩을 쓰고, 박스와 동의 그룹 사이 간격은 24px로 통일한다.
- 체크박스 행과 상세 보기 간격은 12px이며, 체크박스와 상세 보기의 텍스트 시작선을 맞춘다. 본문·동의 라벨·상세 내용의 크기와 줄높이는 같다.
- 파티 안내의 서로 다른 두 문장을 별도 문단으로 나누고, 긴 제목은 의미 단위로 줄바꿈한다.

## 로고 글꼴 변경

사용자 요청으로 로고를 Y클로버체에서 단정한 Pretendard Bold(700)로 변경했다. 기존 로컬 PretendardVariable.woff2를 사용하며, 상단 브랜드와 첫 화면의 찐친소 표시에 적용한다. 본문은 시스템 글꼴을 유지한다.

## 선호 조건 질문 통합

선호 조건 1·2번을 이상형 질문 하나로 통합했다. 기존 상대조건 열과 전송 키는 유지하고 새 접수·수정에서는 빈 문자열로 저장한다. 기존 시트의 과거 행을 일괄 변경하지 않는다. 이전 초안·신청을 열 때 2번의 기존 답변은 1번에 합쳐 입력 손실을 방지한다. 상대조건의 서버 필수 검증을 제거했으며, combinedPreferences 기능 응답으로 새 서버 배포 여부를 확인한다. 실제 접수에는 Code.gs 새 버전 배포가 필요하다.
